浏览器端的文件与文本加密应用。

[在线使用](https://liasica.github.io/cryptnest/) · [下载离线版](https://liasica.github.io/cryptnest/cryptnest-offline.html) · [MIT 许可证](LICENSE)

## 功能

- 文件和文件夹支持选择或拖入，多个文件自动打包为 ZIP
- 文件名、目录结构和内容一起加密，输出 `.cryptnest` 加密包
- 自动生成随机密钥，将封装后的密钥写入结果，任何设备使用本应用均可免密码解密
- 从浏览器可运行的候选算法中随机选择，算法编号与密钥一起加密封装，解密时自动识别
- 文本加密结果使用无前缀的 Base64 编码，支持复制、粘贴和文件导出
- 密钥块的位置、排列顺序和填充长度随机变化，完整性校验覆盖封装结构
- 文件归档解密为 ZIP，文本可复制或下载，支持处理进度与取消
- 兼容版本 `2` 的自动解密结果，以及需要原密码的 `CNEST001` 加密包和文本密文
- 提供「跟随系统」「浅色」「深色」三个主题按钮，默认跟随系统并记住手动选择
- 桌面与手机均可使用，提供包含全部代码的独立 HTML 离线版

## 使用

加密文件时，选择或拖入文件，点击「加密并生成文件」，下载结果。解密时切换到「解密」，选择 `.cryptnest` 加密包，点击解密并下载 ZIP 后解压。需要原密码的加密包会显示密码输入框。

文本处理使用「文本」选项。加密结果可复制为密文，也可下载为 `.cryptnest` 文件。文本解密可直接粘贴密文或选择加密文件。

点击「下载离线版」，保存 HTML 文件并直接用浏览器打开。离线版支持相同的加密与解密操作。

## 数据处理

文件、文本、密码与密钥在当前浏览器中处理，不发送到服务器。应用不使用分析统计、第三方运行时资源、外部字体或网络接口，不将输入内容与密钥写入浏览器持久存储。主题选择可以保存在当前浏览器。

用户导出的结果包含封装后的解密密钥。固定封装规则随开源代码和离线版提供，完整结果的持有者都能解密。随机位置与填充属于格式混淆，不能阻止按照公开规则解密，也不能提供需要独立秘密才能访问的保密性。

生产构建将代码和样式内联到 HTML，内容安全策略的 `connect-src 'none'` 禁用应用联网请求。打包与加密在 Web Worker 内完成。

## 算法与格式

算法使用本地内置的 [`@noble/ciphers`](https://github.com/paulmillr/noble-ciphers) 实现。加密前在 Web Worker 中检查候选算法的加密与解密运行情况，使用浏览器原生 `crypto.getRandomValues` 从可用算法中等概率随机选择。密钥封装固定使用 XChaCha20-Poly1305，内容使用所选算法。

| 算法编号 | 内容算法 | 密钥长度 | nonce 长度 |
| --- | --- | --- | --- |
| 1 | XChaCha20-Poly1305 | 32 字节 | 24 字节 |
| 2 | ChaCha20-Poly1305 | 32 字节 | 12 字节 |
| 3 | AES-256-GCM-SIV | 32 字节 | 12 字节 |

每次加密使用独立的随机密钥和随机 nonce。算法参数参见 [libsodium 文档](https://doc.libsodium.org/secret-key_cryptography/aead/chacha20-poly1305/xchacha20-poly1305_construction) 与 [RFC 8452](https://www.rfc-editor.org/rfc/rfc8452)。解密依据封装中的编号选择算法；认证失败时不尝试其他算法，不能运行指定算法的浏览器会提示更换浏览器。

| 参数 | 值 |
| --- | --- |
| 内容算法 | 从当前浏览器可运行的三种候选算法中随机选择 |
| 内容密钥 | 32 字节，每次独立随机生成 |
| nonce 区 | 密钥封装与内容各占 24 字节；内容按所选算法使用前 24 或 12 字节，其余字节为随机填充 |
| 密钥封装规则 | SHA-256 对固定 UTF-8 字符串 `CryptNest/v3/algorithm-key-envelope` 求摘要，得到封装密钥 |
| 封装元数据 | 1 字节算法编号与 32 字节内容密钥一起加密，附带 16 字节认证标签，共 49 字节 |
| 随机填充区 | 129 ~ 381 字节，包含随机排列的封装元数据与两个 nonce 区 |
| 密钥封装认证数据 | 完整的 16 字节尾部位置表 |
| 内容认证数据 | 完整的填充区与尾部位置表拼接 |

`.cryptnest` 是 CryptNest 的加密容器。ZIP 归档在容器内部，解密得到的 ZIP 可用常规压缩软件打开。文本密文是完整二进制容器的标准 Base64 编码，不附加可见的格式前缀。

格式版本为 `3`。容器依次包含随机填充区、内容密文与 16 字节位置表。密钥封装 nonce、封装元数据、内容 nonce 的顺序随机，每两个块之间以及首尾各有 8 ~ 71 字节随机填充。所有整数使用大端序。

| 位置表内偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 字节 | 二进制标识 `8d 4c e9 71 2f b6 a3 03`，末字节为格式版本 |
| 8 | 2 字节 | 填充区总长度 |
| 10 | 2 字节 | 密钥封装 nonce 在填充区内的偏移 |
| 12 | 2 字节 | 封装元数据在填充区内的偏移 |
| 14 | 2 字节 | 内容 nonce 在填充区内的偏移 |

内容密文末尾包含 16 字节认证标签。解密后的首字节标识内容类型：`1` 表示 ZIP，`2` 表示 UTF-8 文本。后续字节为原始内容。解密前检查位置表范围与块之间的重叠情况，认证失败的结果不输出明文。

### 版本 2

版本 `2` 的二进制标识为 `8d 4c e9 71 2f b6 a3 02`，填充区为 128 ~ 380 字节，位置表结构相同。封装块仅包含 32 字节内容密钥与 16 字节认证标签，内容与密钥封装均使用 XChaCha20-Poly1305。固定封装密钥由 SHA-256 对 `CryptNest/v2/XChaCha20-Poly1305/key-envelope` 求摘要得到，两个 nonce 各为 24 字节。

### 密码格式

`CNEST001` 加密包使用 AES-256-GCM、PBKDF2-HMAC-SHA-256、600,000 次迭代、32 字节随机盐、12 字节随机 IV，以及完整 56 字节文件头作为认证数据。文本支持带 `cryptnest:v1:` 前缀或无前缀的标准 Base64。解密需要原密码，密码区分大小写、空格与 Unicode 字符，不进行修剪或规范化。

文件头依次为 8 字节 UTF-8 标识、4 字节迭代次数、32 字节盐和 12 字节 IV，后续为包含 16 字节认证标签的 AES-GCM 密文。

## 处理范围

- 一次最多加密 1,000 个文件，原始文件总大小不超过 100 MiB
- 文本原始内容不超过 1 MiB，密码长度不超过 1,024 个字符
- 一次解密一个加密包，输入加密包不超过 110 MiB
- 拖入目录的层级不超过 32 层，空目录不写入归档
- 重名文件自动添加序号，ZIP 内保留文件相对路径和修改时间
- 支持带 Web Crypto API 与 Web Worker 的现代浏览器，在线版使用 HTTPS

## 本地开发

使用 `.nvmrc` 指定的 Node.js 版本。

```sh
nvm use
npm ci
npm run dev
```

```sh
npm run check
npm run build
npm run preview
```

构建结果为 `dist/index.html` 和 `dist/cryptnest-offline.html`。新增依赖和发布工具使用核对后的最新稳定版本，准确版本保存在 `package.json` 和 `package-lock.json`。

## 发布

`master` 分支推送触发 GitHub Actions，构建并发布到 GitHub Pages。工作流使用 `.nvmrc` 中的 Node.js 版本，官方 Actions 固定到最新稳定版本对应的提交。

仓库设置中的 Pages 发布来源为 GitHub Actions。
